# old-code · 古法编程

帮助你跟上 AI 正在开发和维护的代码，逐步具备自己判断、排错和修改的能力。每轮围绕一条真实代码路径，得到可追溯的解释、验证证据和一份简短的维护结论，并通过你自己的预测或小练习检验理解。

这里的“古法”指认真建模、查证、推演和承担工程判断。AI 可以继续承担大量实现工作；你的注意力集中在系统必须保证什么、保证在哪里成立、什么时候会失效，以及怎样验证。高可靠性与性能优化需要实际证据，不能靠学习仪式或一段看起来可信的解释保证。

## 三种用法

- **伴随开发**：“这次实现继续推进，带我理解最关键的设计选择，每次只练一个知识点。”
- **接手项目**：“这个模块主要由 AI 写成。带我沿一个请求走通，让我知道以后改需求从哪里下手。”
- **专项练习**：“先别告诉我答案，让我推演这段并发代码的执行结果，再用实验验证。”

默认围绕当前工作伴随学习。你也可以说“今天只解释，不提问”或“先处理事故，学习稍后”，技能会尊重节奏并明确哪些理解尚未检验。仅想修 bug、做性能测量或学习一个抽象概念时，使用对应工程或教学能力即可。

## 你会得到什么

一次结束时给出“掌控卡”：代码位置、必须保持的条件、失败边界、验证结果，以及你实际完成的独立推理。代码通过测试和你已经理解是两件需要分别举证的事。

关注现实中的三类收益：

| 目标 | 实际做法 |
|---|---|
| 看穿可信外观下的错误 | 对照真实源码与版本适用的规范，构造反例，核验 AI 的关键假设 |
| 处理高后果边界 | 针对共享状态、资源有效期、硬件语义逐步推演，明确模型与实机观察之间的距离 |
| 积累维护直觉 | 先独立预测，再对照证据，并把判断迁移到一个改变后的条件 |

技能不要求对所有代码逐行背诵，不强制手写所有实现，也不自动建立课程或学习台账。练习结果不构成人格或能力评级。

## 安装与调用

本技能随 [harness-engineering-skills](https://github.com/meisijiya/harness-engineering-skills) 分发，已安装该包时按包内方式调用 `old-code`。也可以把仓库地址 `https://github.com/meisijiya/harness-engineering-skills` 交给 Agent，明确只安装 `old-code`；支持 skills CLI 的环境可使用：

```bash
npx skills add https://github.com/meisijiya/harness-engineering-skills --skill old-code
```

上述 GitHub 安装入口需要仓库已包含本版本；本地未推送改动不会经远程安装获得。独立安装需完整保留本目录的 `SKILL.md`、`references/` 和许可文件。是否支持 `/old-code` 斜杠调用由宿主决定，直接说“使用 old-code 带我跟进这次改动”也可表达意图。

## 配置、数据与兼容性

无需 API Key、外部服务、专属子代理或额外配置。最低需要读取代码和与用户交互；验证命令使用目标项目现有工具。没有终端可以做静态推演，但会明确标记运行结论未验证。离线时可读本地代码与已有文档，缺失的一手资料需要保留为待核实项。

技能不自带上传、遥测或持久化程序。代码进入哪个模型上下文仍取决于宿主；不要在学习材料中放入密钥或真实敏感数据。练习默认在对话中完成，只有你要求保存时才使用指定的项目位置。

文本与结构在 Windows 环境校验；macOS、Linux 及不同宿主的真实交互尚未验证。程序静态检查不代表弱模型行为、触发准确率或长期学习收益已获证明。
