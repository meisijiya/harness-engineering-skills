# 证据与风险

## 从后果选择深度

用“判断错了会发生什么”选择验证手段。只加载本轮真正涉及的机制；越接近不可逆数据损失、共享状态或硬件副作用，越需要明确前提和独立证据。低风险改动可以用职责说明、一个边界和已有回归测试完成。

| 风险 | 建模时抓什么 | 能推翻假设的证据 |
|---|---|---|
| 一般业务逻辑 | 输入约束、状态转换、不变量、失败后已发生的副作用 | 边界输入、失败注入、项目已有契约测试 |
| 并发与异步 | 共享状态、检查与更新之间的窗口、同步作用域、取消与重试 | 可控调度或屏障构造交错、线程/任务轨迹；适用时验证线性化点 |
| 内存与资源 | 所有权、别名、有效期、分配和释放、异常退出 | 对应语言的内存检查器、资源计数、调试器；工具未配置就先给操作方案 |
| 性能 | 真实工作负载、瓶颈、渐近成本、分配/I/O/竞争来源 | 相同条件下的基线与候选测量、剖析数据和正确性回归 |
| 驱动与嵌入式 | 芯片修订、寄存器语义、中断/DMA 与缓存可见性、访问顺序 | 厂商手册对应章节、硬件轨迹、目标平台验证；模拟结果不能代替实机结论 |

这些领域需要更严密的证据链，而不是“AI 一定不会”或“人一定能”的身份判断。是否需要专家复核由任务风险与项目要求决定。

## 区分依据

- **源码事实**：能直接指出读取过的文件、符号和行为；注释表达意图，不能代替实现。
- **规范保证**：写清库/语言/设备版本及适用条件，引用实际查阅的来源；规范也可能存在实现差异或勘误。
- **模型推演**：列出初始状态、事件顺序和必要假设，能被另一个人复算。
- **运行观察**：说明命令、环境、输入与实际输出，限定结论的适用范围。
- **未知项**：说明缺什么证据、如何获取、它影响哪个决定。

AI 生成的测试可能重复实现本身的错误。先从需求或不变量推导判据，再选反例；测试期望值不能仅仅取自当前输出。

## 最小反例的方法

1. 明确一个必须成立的条件，例如“库存不能为负”“释放后不再访问”“失败不能留下半次转账”。
2. 找出使该条件成立所依赖的假设，例如“检查和更新之间没人插入”或“异步操作在返回前完成”。
3. 只改变一个前提，写出可复算的输入或事件序列，再选能观察差异的测试。
4. 对照结果修正模型；若修复了实现，用原失败用例和正常路径分别复验。

在隔离的最小示例或项目允许的测试环境运行。涉及设备写入、生产负载或破坏性输入时，沿用项目授权边界，先给方案而不是直接试验。

## 成本与收益

把算法复杂度、运行时机制和实测性能分开。较低的大 O 不保证实际更快；少一次分配的收益取决于负载和瓶颈。没有测量条件时说“需要测量”，同时指出应采集的指标；可靠性要求不能因为优化而被静默降低。
